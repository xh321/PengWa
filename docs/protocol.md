# 碰碰娃数据协议

## 识别与传输

**二维码、附近蓝牙列表与 NFC 碰一碰只用于识别对方；所有用户卡片数据统一通过蓝牙 BLE 传输。**
识别成功不代表交换成功，不写入集邮册。收到完整卡片并完成传输确认后才记录相遇。

主页（出示／读取）和附近娃娃页在有权限、蓝牙开启时广播并扫描；编辑卡片、集邮册、扫码相机打开及退后台时结束前台会话。
扫码完成后返回主页并恢复蓝牙。NFC 不可用不会阻止主页通过二维码识别、蓝牙交换。
开启后台蓝牙广播后，前台服务可在后台只广播、接收交换申请，不主动扫描。

| 识别入口 | 识别信息 | 后续行为 |
|---|---|---|
| 二维码 | 对方 UUID | 扫描蓝牙，匹配身份摘要，发起蓝牙申请；对方同意后交换 |
| 附近娃娃 | 蓝牙预览：名字和身份摘要 | 用户点选设备，发起蓝牙申请；对方同意后交换 |
| NFC 私有 AID | 双向交换 UUID | 读取方匹配蓝牙后发起交换；出示方仅在 30 秒内对刚识别的 UUID 自动同意一次 |
| NFC NDEF 系统拉起 | 出示方 UUID | 读取方发起蓝牙申请，对方确认后交换 |

二维码展示无法证明双方都已经识别对方，因此扫描方仍通过蓝牙向展示方请求确认。身份摘要和 UUID 都不是认证凭据，尚未实现密码学身份认证。

## 身份和发现载荷

本机 GUID 首次生成后保持不变。显示名仍使用 Unicode NFC 规范化、去首尾空白、UTF-8 1–32 字节，
拒绝控制字符、格式字符、不可见空白及其他不可显示字符（规则见 `identity/DisplayNameRules.kt`）。

NFC 和新版二维码共用 `exchange/PeerDiscovery.kt`：

```
[0xD3: 1 字节][UUID: 16 字节，大端]
```

严格要求 17 字节。没有显示名、头像、内容块或图片。D3 与旧版名片编码 01 不兼容，避免将发现误判为卡片交换。
解码得到的占位显示名仅供内部 API 使用，不会直接存入集邮册。

二维码内容为 `pengwa://p/` + 发现载荷的 Base64URL（无填充）。生成保持黑码白底，纠错等级 M。
旧 `pengwa://c/` 二维码和 D2 发现载荷直接拒绝，不进行协议兼容。
新版完整卡片传输要求对方具备新版 GATT 特征；缺少时提示版本不兼容。

## 用户卡片

`identity/UserCard.kt` 定义完整卡片及编解码：

- ID、显示名。
- 可选头像：缩略图的 Base64（JPEG／PNG）。
- 有序内容块，最多 12 个：Text、Link、Social、Image。
- 每个块包含类型、标题、文字、图片和可选主页 URL。标题最多 60 个 UTF-16 code unit，文字和 URL 最多 1000。
- Link 的正文是完整 HTTP(S) URL；Social 的文字是账号，URL 是可选主页。禁止其他协议及带用户凭据的链接。
- 社媒内置 QQ、微信、bilibili、小红书、X、Telegram 六个平台，图标使用随 APK 打包的矢量资源，无需联网加载；“其他”保留自定义平台能力。
- 平台名沿用已有 title 字段，不增加协议字段。WeChat / B站 / Twitter / TG 等旧名称会被识别为对应平台；不认识的名称继续按自定义平台展示。
- 所有社媒块均可复制账号；显式填写的 HTTP(S) 分享链接优先。未填写链接时，bilibili 数字 UID、X 和 Telegram 的安全用户名可生成访问链接（支持前导 @）；QQ、微信、小红书只按原账号展示和复制，不根据账号猜测主页地址。不会验证账号是否真实存在。
- 系统图片选择器导入时先缩小再重新编码，移除原始元数据；小图有 alpha 通道时使用 PNG 保留透明轮廓，其余使用 JPEG。头像最长边 192 像素，小图最长边 384 像素；单图压缩后最多 12 KiB；超限时继续等比例缩小。
- 接收端校验 Base64、JPEG 或 PNG 首尾标志和体积；展示前检查图像尺寸不超过 1024×1024，不能解码时显示占位提示。
- 卡片内容依次放入可容纳该块的最靠上的空位，允许后续小块回填跨列块上方空洞，使用 1–3 列自适应瀑布流；链接默认横跨两格，社交和图片默认一格，文字正文在单格下达到三行或标题达到两行时扩为两格，短文字保持一格，随可用宽度和字体比例减少列数。单个社交块仍保持一格，链接在列数不足时回退到一列。默认占格只影响展示，不新增传输字段。展示与编辑预览共用布局，编辑操作仍为有序列表。
- 小图块在预览和收到的卡片中只展示图片，不展示标题、卡片底框或圆角裁剪；编辑区不提供小图标题输入。横图、竖图和透明不规则图按原比例缩放到可用空间。旧标题保留作无障碍描述，不改变原数据格式。
- 整张编码后的卡片上限 96 KiB；超限保存失败，编辑草稿保留。

### 编码

所有整数均为大端。字符串使用 Java `DataOutputStream.writeUTF` / `DataInputStream.readUTF` 的 modified UTF-8，
以无符号 16 位编码字节长度开头（跨平台实现注意 NUL 和代理项的编码）。

```
[int32 magic = 0x50574332 (PWC2)]
[int32 基础身份字节数][基础身份]
[UTF 头像 Base64]
[int32 内容块数量]
重复每个块：
  [UTF 类型名][UTF 标题][UTF 正文][UTF 图片 Base64][UTF 可选主页 URL]
```

基础身份继续使用 `[01][16 字节 UUID][UTF-8 显示名]`，18–49 字节。
该结构只是完整蓝牙卡片中的身份字段和旧版蓝牙兼容结构，不再作为新版二维码／NFC 的名片传输格式。
未知版本、未知内容块类型、非法名字、数量／体积越界、截断和多余尾部字节均拒绝整张卡片。

## 蓝牙 BLE

实现位于 `ble/BleExchangeManager.kt`、`CardTransfer.kt`、`GattExchangeSessions.kt` 和 `BleExchangeController.kt`。

| 项目 | UUID | 用途 |
|---|---|---|
| 服务 | `da9c7844-c076-4b1e-9a5f-b9433bc5bac2` | 可连接广播，只广播此服务 UUID |
| 旧预览 | `8ce4c75f-2186-46c3-8cbb-0878f1776ab4` | 只读 `[01][UTF-8 显示名]` |
| 身份预览 | `21e42f2e-31a7-4ea4-a8bb-6e0306d532fa` | 只读 `[01][身份摘要 16 字节][UTF-8 显示名]` |
| 状态 | `a27c16b7-0d98-4c22-b9bc-02ae6ed62b39` | 只读申请决定 |
| 完整卡片 | `98af05e8-12f7-4d33-8850-69ddac40c2b2` | 读写分块数据和控制帧 |
| 旧名片 | `f5181d1f-bfb7-44d6-bc07-6e14fa5eb21a` | 旧客户端获准后只读基础身份 |
| 旧申请 | `9826f54e-83fb-4b2c-8fad-a9714333290e` | 旧客户端写基础身份申请 |

身份摘要是 `SHA-256(UTF-8("pengwa:nearby:v1:") + UUID 大端字节)` 的前 16 字节。
二维码／NFC 得到 UUID 后计算摘要，与蓝牙身份预览匹配；收到的完整卡片 UUID 还必须与识别目标相同。
列表按摘要去重，同名不同人不合并；旧预览缺少摘要时仍可手动点选。

状态：0 等待、1 同意、2 拒绝、3 过期、255 未申请。普通申请继续使用防骚扰规则：最多 3 条待处理，
60 秒未处理过期，拒绝后同一 UUID 冷却 10 分钟。前台弹对话框，后台发通知。

### 分块交换

1. 发起方连接、协商 MTU（请求 517，仍兼容默认 23），查找完整卡片特征；缺少时中止并提示升级。
2. 将本机完整卡片快照分块写入该特征。每帧为 `[int32 offset][int32 total][payload]`，
   写入帧不超过 `min(MTU - 3, 512)`。每次等待 GATT 写确认再发下一帧。
3. 接收端只接受连续 offset、恒定 total、上限内的完整数据。未收齐或校验失败不产生有效申请，不写库。
4. 收齐后校验并发起申请。发起方每秒读一次状态，最多等 65 秒；对方获准前不能读取卡片。
5. 同意后，发起方写控制帧 `[int32 期望读取的 offset][int32 -1]`，再读同一个特征。
   返回 `[int32 offset][int32 total][payload]`，不超过 `min(MTU - 2, 510)`，刻意短于 ATT 最大读取响应，避免 Android 自动长读。
   服务端保持本次卡片快照，要求连续读取，可重读上一块。
6. 发起方收齐、解码并验证目标 UUID 后，写确认帧 `[int32 -1][int32 0]`。
   服务端确认所有块已提供且未重复确认，触发保存收到的卡片；发起方在确认写成功后保存收到的卡片。
7. 断开清理会话、未完成缓冲与申请。连接／交换总期限 180 秒，失败通过列表和主页状态反馈，可重试。

单连接最多暂存 96 KiB 输入；最多保留 16 个输入会话。分块不使用 GATT prepared write。
发现等待匹配的期限为 30 秒，连接后由蓝牙交换期限管理；整个交换不是跨设备分布式事务，
最后确认或本地写库时故障可能导致单侧已有记录，重新交换由相遇防抖减少重复计数。

网络协议仅支持当前版本，使用独立服务 UUID，不提供旧式基础身份交换或回退。本地历史卡片仍可读取。
完整卡片的空内容可清空旧内容；旧式基础身份相遇不会覆盖已有头像与内容块。

## NFC ISO-DEP / HCE

私有 AID `F050454E475741`，保留现有读取／出示角色、默认钱包引导和生命周期控制。

| 步骤 | 命令 | 响应 |
|---|---|---|
| SELECT | `00 A4 04 00 07 F050454E475741 00` | `90 00` |
| 识别 | `80 E0 00 00 11 [D3 + 发起方 UUID] 00` | `[D3 + 出示方 UUID] 90 00` |

必须先 SELECT；切页、角色切换、后台或 deactivation 清理会话。合法识别仅通知蓝牙控制器，不调用相遇记录器。
生产入口显式使用 `discoveryOnly=true`，旧基础名片 NFC 载荷不再被接受。
标准 NDEF 标签仍使用 `application/vnd.pengwa.card` MIME，但负载改为 D3 发现载荷；系统拉起后也只启动蓝牙连接。
私有 AID 归 payment，标准标签 AID `D3760000850101` 归 other；厂商钱包路由争用仍需真机按机型验证。
调试日志只记录命令头、状态、耗时和生命周期，不记录载荷或身份 UUID。

## 本地存储与验证

自己的卡片保存在 identity SharedPreferences，保存前校验并同步确认写入；编辑使用 ViewModel 草稿，
旋转或系统图片选择器返回后保留本次草稿。集邮册 SQLite 从版本 1 升到 2，新增 nullable `card BLOB`，保留原来的名字、时间和相遇次数。

自动测试覆盖卡片往返、MTU 23/64/247/517 分块、乱序／重复／长度变化／超限、非法内容与链接、
NFC 只识别、旧版 NFC 拒绝、二维码只含发现载荷与旧码只提取身份。原有单元测试继续运行。
模拟器 UI 与持久化验证及运行截图见 [custom-card 截图说明](screenshots/custom-card/README.md)。
当前尚未完成双 Android 真机的 NFC → BLE、二维码 → BLE、附近列表 → BLE 端到端验证，不能据此宣布实机传输验收通过。
