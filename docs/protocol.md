# 碰碰娃数据协议

Android 与将来的 iOS 版共用这份规格。名片编码实现位于 `app/src/main/kotlin/app/pengwa/ble/BleProtocol.kt`。

## 总览：面对面交换与蓝牙分组

主页顶部显示我的名片，下面是 **碰一碰 / 扫码、蓝牙** 两个可左右滑动的页。默认页同时提供 NFC 出示／读取与二维码，无需先切换方式。**三种方式交换的是同一张名片**
（同一套字节编码，见下文），区别只在传输通道。

停在哪一页，应用里就启用对应分组，其余关闭（`exchange/ExchangeMode.kt`，全应用共享一份状态，
NFC 服务、蓝牙总控、前台 NFC 角色控制都读它）：

| 当前页 | 生效的东西 | 关闭的东西 |
|---|---|---|
| 碰一碰 / 扫码 · 出示 | 私有 AID 和标签 AID 都响应，等对方读取；同时展示我的二维码并可一键扫码 | 蓝牙不广播不扫描 |
| 碰一碰 / 扫码 · 读取 | Reader Mode 直接读取对方的私有 AID，本机不模拟名片；同时展示我的二维码并可一键扫码 | 同上 |
| 蓝牙 | 广播并扫描，列出附近的人，**点谁才向谁申请，对方同意后才交换** | NFC 不响应、不接收；相机关闭、亮度恢复 |
| 都不是 | 切到别的底部页、退到后台、息屏、正在改名 | 全部关闭 |

以"停稳"的那一页为准（`settledPage`），滑动途中经过的页不会被启用。
例外有两个：
1. 别人展示了名片、被系统用 NDEF 标签拉起本 App 时，我们收下对方名片，这条路径不受当前页限制
   （对方明确展示了名片）。
2. **后台蓝牙广播**：用户在"设置"里打开后，前台服务在后台持续**只广播、不扫描**，不受当前页限制，
   等别人来申请（见下文蓝牙一节）。

**谁需要同意**：NFC 和二维码是面对面的主动动作，不需要同意；蓝牙因为可能是后台被动广播，
**被申请的一方必须同意**才会交换。

## 身份

| 字段 | 说明 |
|---|---|
| ID | GUID（UUID v4），首次启动时随机生成并永久保存；清除数据或重装后会重新生成 |
| 显示名 | 用户自定义，Unicode NFC 规范化，去首尾空白，UTF-8 编码后 **1–32 字节** |

显示名只允许可显示字符，拒绝：控制字符、格式字符（零宽空格 / 连接符、方向覆盖符等）、
换行、代理项残片、私有区、未分配码位、除普通空格外的所有空白，以及韩文填充符（U+115F、U+1160、U+3164、U+FFA0）
和盲文空白（U+2800）。因此 ZWJ 连接的复合 emoji 不可用。
**接收方必须对收到的名字再执行同一套校验**，不合法则整条丢弃。

## 名片编码（NFC、蓝牙、二维码共用）

```
偏移  长度  内容
0     1     版本号，当前为 0x01
1     16    GUID，大端（与 UUID 文本从左到右的字节顺序一致）
17    1–32  显示名，UTF-8
```

总长 18–49 字节。接收方遇到以下任何情况都应丢弃：版本号不是 0x01、总长不在范围内、
UTF-8 非法、名字不是规范形式、名字未通过校验。

## 二维码

实现：`qr/QrPayload.kt`（内容）、`qr/QrCodec.kt`（生成与识别，基于 ZXing core）。

- **内容**：`pengwa://c/` + 名片字节的 base64url（无填充）。最长约 77 个字符，二维码约 41×41 个模块。
- **生成**：纠错等级 M，不带静区，由界面留白；固定黑码白底，不随深色主题变化（否则很多扫码器识别不了）。
- **识别**：CameraX 逐帧送亮度平面（带行跨度），ZXing 识别；二维码识别与图像旋转无关，不需要转正。
  扫到的内容来自外部，解码时重新校验，不合法返回 null，界面提示"这不是碰碰娃的二维码"。
- **一次扫描是单向的**：扫的人拿到对方的名片，对方要拿到自己的需要也扫一次我的码。
- **亮度**：在碰一碰 / 扫码页展示自己的二维码期间，用窗口亮度覆盖（`screenBrightness=1.0`）把亮度拉到最高并锁定、屏幕保持常亮，
  不需要"修改系统设置"权限，不动用户的系统亮度值；打开扫码、切走或退到后台立即恢复。
  已用 `dumpsys` 确认：亮度来源变为 `override(app.pengwa.debug/…MainActivity)`，自动亮度被禁用，
  离开后恢复为 `automatic`。注意"最高"指普通亮度上限（实测 230/255），不含强光下系统才会启用的额外亮度。
- **相机权限**：只在点"扫一扫"时才申请；离开这一页（点关闭、滑走、退到后台）立即解绑相机。

## 蓝牙（BLE）

实现：`ble/BleExchangeManager.kt`（GATT 与队列）、`ble/BleExchangeController.kt`（总控）、
`ble/BleBroadcastService.kt`（后台前台服务）、`ble/NearbyList.kt`（列表模型）、`ble/GattExchangeSessions.kt`
（申请—同意状态机）、`ble/IncomingRequests.kt`（待处理申请与防骚扰）。除 Android 胶水外都是纯 Kotlin。

| 项目 | UUID | 属性 |
|---|---|---|
| 服务 | `da9c7844-c076-4b1e-9a5f-b9433bc5bac2` | |
| 预览特征 | `8ce4c75f-2186-46c3-8cbb-0878f1776ab4` | 只读：`[版本][UTF-8 显示名]`，**不含 ID**，不需要申请 |
| 状态特征 | `a27c16b7-0d98-4c22-b9bc-02ae6ed62b39` | 只读：1 字节，我对这个连接发来的申请做了什么决定 |
| 名片特征 | `f5181d1f-bfb7-44d6-bc07-6e14fa5eb21a` | 只读：名片编码，**申请被同意之后才允许读** |
| 交换特征 | `9826f54e-83fb-4b2c-8fad-a9714333290e` | 只写：对方出示它的名片 = **向我申请交换** |

状态码：`0` Pending（等待我决定）/ `1` Accepted（同意）/ `2` Declined（拒绝，含自动拒绝）/ `3` Expired（超时）/
`255` None（这个连接还没有发过申请）。

- **广播**：可连接广播，数据里只含服务 UUID。**不放 ID 和名字**，避免被路人被动收集。
  已用另一台设备（电脑蓝牙）确认广播里没有设备名和厂商数据。
- **附近的人列表**：扫到广播后连接一次，读「预览特征」拿到显示名，列在蓝牙页上，按信号从强到弱排序。
  名字只在对方开着蓝牙页或后台广播时才可被读到（用户主动选择"让附近的人发现我"）；ID 仍受申请—同意保护。
  同一个设备最多读 2 次预览，读不出来就显示"附近的碰碰娃"；超过 15 秒没再扫到就移出列表。
- **申请—同意流程**（被申请方必须同意）：
  1. 申请方点某个人 → 连接 → 协商 MTU（建议 ≥ 64）→ **把自己的名片写入对方的「交换特征」**。
     写入成功只代表**申请已送达**，不代表同意。服务端校验名片（版本、UTF-8、显示名规则），不合法就拒绝写入。
  2. 申请方**每秒读一次「状态特征」**，最多等 65 秒。界面显示"等待对方同意…"。
  3. 被申请方弹出提示：应用在前台时是**对话框**（点外面或返回键不算决定，必须明确选），
     在后台时是带"**同意 / 拒绝**"按钮的**通知**（同意按钮要求先解锁）。同意后状态变 1，拒绝变 2，
     60 秒没人处理变 3。
  4. 状态为 1 后，申请方才能读「名片特征」；此时被申请方也把申请方记入集邮册，**双方同时入册**。
     状态为 2 或 3，申请方得到"对方拒绝了交换 / 对方没有回应"，名片特征始终拒绝读取
     （GATT 错误 `INSUFFICIENT_AUTHORIZATION 0x08`）。
  5. 申请方在被同意之前断开连接，被申请方的提示自动撤销，不算拒绝。
- **防骚扰**（被申请方）：同时最多 3 条待处理申请，超出的自动拒绝；**拒绝过的人**（按名片里的 ID 认人，
  不是设备地址）10 分钟内再申请自动拒绝，不再弹窗；同一个连接重复申请只保留一条。
- **所有主动连接**排进一个串行队列（同一时刻只有一个），用户点选的排在最前面。
- **后台广播**：用户在"设置"里打开"后台蓝牙广播"（默认关闭）后，由**前台服务**（类型 `connectedDevice`）
  在后台持续**只广播、不扫描**，用低功耗模式；前台蓝牙页则用低延迟模式并且同时扫描。
  前台服务必须有常驻通知，所以这条通知就是"常驻通知"（自定义布局，多一行"蓝牙广播中"），
  开着后台广播时"常驻通知"开关被锁定为开。需要权限：附近的设备（广播、连接）和通知（用来提醒有人申请）。
  重启手机或强行停止后**不会自动恢复**，需要再打开一次应用。
- **运行条件**：蓝牙页（前台）需要三项蓝牙权限；后台广播只需广播和连接两项。系统蓝牙没开则都不运行。
  离开蓝牙页立即停止扫描并清空列表；关掉后台广播或没有任何场景需要时，停止广播并关闭 GATT 服务。
- **iOS 注意**：CoreBluetooth 广播只能带服务 UUID 和本地名称，不能带自定义数据，所以本协议不依赖广播负载。

## NFC（ISO-DEP / HCE）

实现：`nfc/ApduProtocol.kt`（协议，纯 Kotlin）、`nfc/PengWaHostApduService.kt`（被碰一方）、
`nfc/NfcTagExchanger.kt`（碰别人一方）。测试：`ApduProtocolTest`，其中有把两端直接对接的整次碰触测试。

- **AID**：`F050454E475741`（`F0` 私有应用前缀 + "PENGWA" 的 ASCII），category `payment`（获得默认钱包资格，仍只处理碰娃私有协议）。
- **一次碰触、一次往返完成双向交换**：

| 步骤 | 发起方 → 被碰方（命令） | 被碰方 → 发起方（响应） |
|---|---|---|
| 1 SELECT | `00 A4 04 00 07 F050454E475741 00`（即 AID） | `90 00` |
| 2 EXCHANGE | `80 E0 00 00 Lc [发起方名片] 00` | `[被碰方名片] 90 00` |

- 名片编码见上文，最长 49 字节，在短 APDU 的 255 字节数据域内。
- **会话约束**：必须先 SELECT 成功才接受 EXCHANGE；设备断开（`onDeactivated`）后需重新 SELECT。
- **互惠约束**：被碰方只在收到合法名片后才返回自己的名片，通用读卡器无法白拿；
  这不是安全措施（协议公开），只是避免随手抄走。
- **模式开关**：只有 碰一碰 / 扫码页的“出示”角色响应卡命令。切到“读取”、离开页面或退到后台后，拒绝命令并清掉会话。每次重新进入“出示”都会换一个会话编号，
  即使离开期间没有收到命令，也必须重新 SELECT，旧私有协议／NDEF 会话不会复活。
- **状态字**：`6A82` AID 不匹配或本机未在 碰一碰 / 扫码页 / `6985` 未 SELECT 或本机还没设置名字 / `6A80` 名片不合法 /
  `6700` 长度错误 / `6D00` 不支持的指令 / `6E00` 不支持的 CLA。
- **角色分工**：默认“出示”；双方打开 碰一碰 / 扫码页后，一方选择“读取”，另一方保持“出示”。两台都选同一种角色不会交换。
- **读取**：`enableReaderMode` 使用 `FLAG_READER_NFC_A | FLAG_READER_SKIP_NDEF_CHECK`，
  通过 `IsoDep` 直接 SELECT 私有 AID，不先探测标准 NDEF 标签。Reader Mode 会关闭本机卡模拟。
- **钱包兼容提示**：所有品牌在本应用尚非默认钱包时，NFC 出示页均提供“设为默认钱包”入口。Android 15+ 使用 `RoleManager.createRequestRoleIntent(ROLE_WALLET)` 请求本应用的钱包角色，旧系统使用指定本服务的 `CardEmulation.ACTION_CHANGE_DEFAULT`。
  系统请求返回和页面恢复前台时都重新查询实际默认状态：成为默认钱包后隐藏提示，取消则继续显示，切回其他钱包再返回时重现。
  系统确认入口不可用时回退到 `Settings.ACTION_NFC_PAYMENT_SETTINGS`、NFC 设置、默认应用设置和系统设置，全部失败则给出手动搜索提示。
  钱包是否为本应用不影响出示会话启动；部分机型使用其他第三方钱包为默认时也能正常前台 HCE。
  切换可能影响原钱包的银行卡、交通卡和门禁卡，使用原钱包前需手动切回；切换经系统界面确认，应用不自动恢复原钱包，也不请求系统设置写入权限。
- **出示**：调用 `setPreferredService` 并检查返回值；移除需要特殊权限且未解决本次问题的 discovery 覆盖调用。
  私有 AID 归 payment，使本应用可被用户选为默认钱包；仍只处理碰碰娃私有协议，不注册银行卡 AID。
- **生命周期**：切换角色先释放旧配置；离开出示页、进入系统设置或 `onPause` 时关闭 Reader Mode／撤销前台首选服务，返回后恢复页面对应会话。
- 双方需解锁并保持 App 前台；`requireDeviceUnlock=false` 只是服务声明，不表示本 App 会在后台开放名片。

## NFC 标签模拟（标准 AID，让对方系统直接拉起 App）

实现：`nfc/NdefMessages.kt`、`nfc/T4tEmulator.kt`（含 `CardRouter`）、`nfc/NdefLaunchParser.kt`。
测试：`T4tEmulatorTest`（有一个按 NFC Forum 规范读标签的"标准读卡器"）。

同一个 HCE 服务同时响应两个 AID，由 `CardRouter` 按最近一次成功的 SELECT 决定后续命令交给谁：

| AID | 用途 | 对方需要装 App 吗 |
|---|---|---|
| `F050454E475741`（私有） | 两边都装了 App，一次碰触双向交换（上一节） | 需要 |
| `D2760000850101`（NFC Forum NDEF 标签应用） | 被任何手机当作一张标签读取；系统据此直接拉起 App | 读的一方不需要装 App 也能读到数据，但只有装了才会被拉起 |

- **标签内容**：一条 NDEF 短记录，TNF=媒体类型，类型 `application/vnd.pengwa.card`，负载为上文的名片编码。
  整个 NDEF 文件 = 2 字节长度（大端）+ 消息，最长 81 字节。
- **能力文件**（E103，15 字节）：映射版本 2.0、MLe 59、MLc 52、NDEF 文件 E104 最大 255 字节、读不限制、写禁止。
  读卡器按规范依次：SELECT 应用 → SELECT E103 → READ BINARY → SELECT E104 → READ BINARY（分多次，每次最多 59 字节）。
- **App 被拉起**：`MainActivity` 声明了 `NDEF_DISCOVERED` + 上述 MIME 的过滤器，系统直接拉起 App，**不经过网站**。
  意图内容来自外部，解析时重新校验（版本号、UTF-8、显示名规则），不合法的丢弃。
  这条兼容入口只收下展示方的名片；需要双方交换时，双方打开 碰一碰 / 扫码页并分别选择“出示”和“读取”。
- **只在 碰一碰 / 扫码页的出示角色响应**：其他角色下 SELECT 标准 AID 返回 `6A82`，读卡方看到的就是
  "这不是一张 NDEF 标签"。滑走、退到后台、进程被杀都会关闭。
- **AID 争用**：标准 AID 不是我们独占的，系统自带服务也可能登记它。“出示”角色通过
  `CardEmulation.setPreferredService` 声明首选，离开自动撤销。私有 AID 归 payment 类别、NDEF AID 归 other 类别；出示不强制要求持有默认钱包，厂商路由行为需按机型验证。
  `PengWaNfc` 日志记录角色、首选服务结果、SELECT 类型与结果、交换阶段，不输出名片内容。排障时可用
  `adb logcat -s PengWaNfc`，对照 `adb shell dumpsys nfc`；若仍触发钱包，可直接使用本页二维码交换。
  Debug / Nightly 版也可先在主页复现，再连点 NFC 状态图标 5 次进入隐藏的实验室，点“复制 NFC 日志”。
  日志包含机型、系统版本、构建提交号、角色与生命周期、配置调用结果、标签技术、APDU 命令头、响应状态码和耗时；
  不记录姓名、身份 GUID、标签 UID、APDU 数据域或响应名片。界面显示最近 60 条，复制最近 400 条（旧到新），可清空；
  日志只保存在进程内，退出进程后清空。Release 版不收集这份诊断日志，也无法通过手势或页面参数打开实验室。
- **没装 App 的人**：什么都不会发生。要让他们看到下载页，需要把第一条记录改成 `https` 网址并配置 App Links
  （见 `docs/release.md`）。名片编码保持不变，只是外面的包装从自定义 MIME 换成网址。

## 验证状态

以下为合并前版本的真机记录（一部 Android 16 手机，必要时用电脑蓝牙当第二台设备）。本次合并页面的实际 NFC 碰触与实物扫码仍需真机复测：

- **蓝牙，手机当申请方**：电脑扮演另一台碰碰娃（GATT 外围设备 + 广播），手机在蓝牙页扫到、读到名字并列出；
  点"申请交换"后显示"等待对方同意…"，电脑那边看到手机**每秒查询一次状态**（0,0,0,0 → 1），
  同意后手机才读到电脑的名片并入册。电脑设为拒绝时，手机显示"对方拒绝了交换"和"重试"。
- **蓝牙，手机当被申请方**：电脑当申请方，通过真实蓝牙向手机发申请——
  申请前状态为 None 且读名片被拒；乱数据、带零宽字符的名字都被拒且状态不变；合法申请后状态 Pending，
  **用户点同意之前读名片一直被拒绝**；点同意后状态 Accepted 并读到手机的名片；点拒绝后状态 Declined 且仍读不到；
  同一个人紧接着再来被**冷却规则自动拒绝**，手机不再弹窗。
- **后台广播**：打开开关后前台服务启动（`isForeground=true`，类型 `connectedDevice`，通知是自定义常驻通知）；
  应用退到后台后电脑仍然扫到手机的广播；关掉开关后服务停止、电脑 20 秒扫不到。后台用低功耗广播。
- **申请提示**：应用在前台时弹对话框（点外面和返回键都不会让它消失）；同意后对方入册，拒绝则不入册；
  超过 60 秒无人处理的申请自动过期并记入日志。
- 蓝牙广播内容：只有服务 UUID，没有名字和厂商数据。
- 模式切换：NFC 页的首选服务在滑走后撤销；蓝牙页之外不广播、不扫描；二维码页之外亮度恢复。
- 二维码：对真机截图用独立的 ZXing 解码，还原出与 NFC、蓝牙相同的名片；相机在关闭、滑走时立即释放。
- 相机权限：撤销后点击，系统弹窗正常出现，授权后相机被碰碰娃占用（`dumpsys media.camera`）。

**尚未验证**（需要第二部手机或实物）：

- 两部手机之间的真实 NFC 碰触：明确“出示／读取”后是否稳定交换、切换角色后是否恢复正常；
  iPhone 能否读到安卓模拟的标签。
- 用相机扫一个真实的二维码（识别逻辑有单元测试，包括带行填充的相机帧，但没有在真机相机前扫过实物）。
- 蓝牙：两部手机互相选中时的并发行为（比如同时互相申请）。
- **后台通知上的"同意 / 拒绝"按钮**：通知内容已确认（标题、正文正确），但这台测试手机开着勿扰，
  通知被三星"通知滤盒"和用户自己的第三方滤盒应用拦截并消除，没能从通知栏点按钮；按钮背后的处理
  与对话框走同一个入口（`respond`），已通过对话框验证。需要关闭勿扰后实测一遍。
- 后台广播的**长时间存活**（数小时、息屏、省电模式、厂商后台管理）：只验证了启动、退到后台后仍在广播和关闭。
- 重启手机后的恢复（没有做）。
