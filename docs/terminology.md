>
> 覆盖：应用页面、按钮、状态、错误、通知、无障碍文本、权限说明、NFC 系统组件、卡片编辑器和调试版实验室。

## 1. 核心术语决策

| 编号 | 概念 | 旧写法 | 标准词 | 使用边界 |
| --- | --- | --- | --- | --- |
| D01 | 中央交换页面 | 扩列、主页、碰一碰、名片页 | **扩列** | “扩列”只作页面名；通知按钮、返回按钮及导航说明也用“扩列”。“碰一碰”只指 NFC 动作，“我的卡片”只指页面中的对象。备选：主页。 |
| D02 | 用户身份载体 | 名片、卡片、完整卡片 | **扩列卡片（全称）／卡片（简写）** | 已确认。正式定义、功能介绍或首次出现时用“扩列卡片”；上下文明确、按钮、状态或空间受限时用“卡片”。用户界面不再使用“名片”，代码中的 `Card` 等模型名不受影响。 |
| D03 | 附近用户及页面 | 附近娃娃、附近的碰碰娃、附近的人 | **附近娃娃／附近的娃娃** | 页面名用“附近娃娃”，句中指人用“附近的娃娃”；已确定的交互对象用“对方”。 |
| D04 | 已入册用户 | 娃友、附近的人 | **娃友** | 指已经交换卡片并进入集邮册的娃娃。与 D03 的“附近的娃娃”保留阶段差异。 |
| D05 | 用户公开名称 | 显示名、名字、姓名 | **显示名** | 表单、校验、权限及隐私说明统一“显示名”。首次设置的口语标题可保留“给自己起个名字”。 |
| D06 | 娃友照片功能 | 合影、照片 | **合影** | 功能名、数量、查看和移除用“合影”；文件层面仍用“照片文件、系统相册中的原照片”。若允许添加任意照片而非双方合影，建议改选“照片”。 |
| D07 | 卡片图片内容块 | 小图、图片、图片块、卡片图片 | **图片** | 内容块类型用“图片”，特指组成单位时用“图片块”；“小图”只描述压缩后的尺寸。 |
| D08 | 社交内容块 | 社媒、社交账号 | **社交账号** | 内容块类型用“社交账号”；平台选择用“社交平台”；字段用“平台名称、账号、主页链接”。 |
| D09 | 交换成功即时反馈 | 碰到了 xx、卡片交换完成、已交换 | **碰到了 xx** | Snackbar 用“碰到了 xx”；流程状态用“卡片交换完成”；附近列表行用“已交换”。若更强调结果，可改为“已收到 xx 的卡片”。 |
| D10 | 附近列表主按钮 | 交换、申请交换 | **申请交换** | 行为需要对方同意，完整文案更准确；空间不足时可见文字用“申请”，无障碍名称仍用“向 xx 申请交换”。备选：交换。 |
| D11 | 更新构建类型 | Nightly、正式版 | **Nightly／正式版** | `Nightly` 作为更新通道专名保留；备选：测试版。 |

## 2. 品牌、人物与身份

| 标准词 | 定义与固定用法 | 不再推荐／需要替换 |
| --- | --- | --- |
| 碰碰娃 | 应用中文品牌名。 | 普通用户界面不用 PengWa 替代。 |
| PengWa | 包名、目录、技术日志等工程标识，如 `Pictures/PengWa`。 | 不作为中文界面品牌名。 |
| 附近的娃娃 | 被发现的附近用户，尚未交换或入册。 | 附近的碰碰娃。 |
| 娃友 | 已进入集邮册的用户。 | 不与“附近的娃娃”混用。 |
| 对方 | 当前正在扫码、碰一碰或交换的确定对象。 | 不在对象未知时替代附近用户统称。 |
| 显示名 | 用户公开展示的名称。 | 姓名；校验错误中的“名字”。 |
| ID | 默认指界面中缩短展示的标识。 | 不另造“短 ID”，除非需要与完整 ID 并列解释。 |
| 完整 ID | 详情页展示的完整标识。 | — |
| 扩列卡片 | 用户身份载体的完整称谓。正式定义、功能介绍或首次出现时使用。 | 名片。 |
| 卡片 | “扩列卡片”的简写。上下文明确、按钮、状态或空间受限时使用。 | 不在同一句话中反复使用全称。 |
| 我的扩列卡片／我的卡片 | 当前用户自己的身份载体；前者为完整称谓，后者为简写。 | 我的名片。 |
| 对方的扩列卡片／对方的卡片 | 当前交互对象的身份载体；按语境使用全称或简写。 | 对方的名片。 |
| 完整扩列卡片／完整卡片 | 经蓝牙传输的完整内容，区别于用于识别的显示名和 ID；按语境使用全称或简写。 | 完整名片。 |

## 5. 交换方式、动作与状态

### 5.1 概念分层

| 标准词 | 层级与定义 | 固定搭配 |
| --- | --- | --- |
| 扩列 | 产品目的地 | 去扩列、返回扩列。 |
| 交换卡片 | 完整行为与结果 | 申请交换、同意交换、交换失败。 |
| 碰一碰 | NFC 产品动作 | 碰一碰可用、重新碰一碰。 |
| NFC | 技术、系统设置、诊断和兼容性名词 | NFC 区域、NFC 设置、NFC 诊断。 |
| 二维码 | 识别载体名词 | 我的卡片二维码、对方二维码。 |
| 扫一扫 | 扫码主按钮 | 按钮固定用“扫一扫”。 |
| 扫码 | 说明性动作 | 扫码识别对方、重新扫码。 |
| 附近娃娃 | 蓝牙产品入口 | 打开“附近娃娃”。 |
| 蓝牙 | 发现及完整卡片传输的技术通道 | 开启蓝牙、蓝牙连接、蓝牙交换。 |

### 5.2 交换动作

| 标准词 | 定义与固定用法 |
| --- | --- |
| 出示我的卡片 | NFC 出示角色；句中可简称“出示”。 |
| 读取对方卡片 | NFC 读取角色；句中可简称“读取”。 |
| 发现 | 找到附近对象，不代表已确认完整身份。 |
| 识别 | 通过 NFC、二维码或蓝牙确认对方身份。 |
| 搜索 | 用户界面持续查找附近对象。 |
| 扫描 | BLE 技术日志用语，普通界面优先“搜索”。 |
| 申请交换 | 主动向对方发起需要同意的请求。 |
| 交换申请 | 请求本身的名称及通知渠道名。 |
| 同意交换 | 应用内明确接受申请；空间受限的通知按钮可用“同意”。 |
| 拒绝 | 拒绝交换申请。 |
| 重试 | 重试当前明确操作。 |
| 重试连接 | 明确需要重新建立蓝牙连接。 |
| 去交换卡片 | 从集邮册空状态前往交换入口。 |

## 9. 通用动作、状态与错误句式

| 类别 | 标准写法 | 规则 |
| --- | --- | --- |
| 通用动作 | 保存、取消、返回、关闭、编辑、预览、重试 | 按钮使用动词或明确的动宾短语。 |
| 开关动作 | 开启 | 设置说明也用“开启后”，避免与“打开后”混用；打开应用或页面仍用“打开”。 |
| 复制动作 | 点击复制、已复制 | 社交账号的可见提示及无障碍状态。 |
| 加载状态 | 正在…／…加载中 | 进行状态统一使用省略号 `…`，不使用三个句点。 |
| 完成状态 | 已…／…完成 | 如“已复制”“已交换”“卡片交换完成”。 |
| 失败状态 | …失败／无法…／未能… | 优先说明失败对象，并给出可执行的恢复动作。 |
| 权限不足 | 没有…权限／需要…权限 | 系统权限名保持 Android 官方叫法。 |
| 功能关闭 | …未开启 | 如“碰一碰未开启”“系统蓝牙未开启”。 |
| 能力缺失 | 此设备不支持…／此设备无法… | “不支持”表示能力缺失，“无法”表示当前操作不能完成。 |
| 数据无效 | …无效／…不合法 | 后续可再统一校验口吻；当前不属于同义词冲突。 |

## 11. 固定写作规则

1. **产品语言与技术语言分层**：普通用户看到“碰一碰、扫一扫、附近娃娃”；系统设置、兼容性和诊断中保留“NFC、BLE、GATT、扫描”。
2. **对象与动作分层**：二维码是对象，扫一扫是按钮，扫码是说明动作；扩列是页面，交换卡片是行为。
3. **阶段称呼分层**：附近的娃娃是尚未入册的发现对象，娃友是已入册对象，对方是当前交互对象。
4. **按钮明确动作**：优先“申请交换、同意交换、保存卡片、安装更新”，避免只有上下文才能理解的泛化按钮；空间不足时可缩短可见文字，但无障碍名称保持完整。
5. **状态句式一致**：进行中用“正在…”，完成用“已…”，失败用“…失败／无法…”，并尽量附恢复动作。
6. **移除与删除不机械合并**：解除应用内关联且保留系统原文件用“移除”；删除内容块等数据用“删除”。
7. **权限名称不自行改写**：使用“附近的设备、通知、相机”等 Android 官方名称。
8. **中英文之间留空格**：如“完整 ID、NFC 区域、QQ 号、X 用户名”；品牌专名和固定路径除外。
9. **省略号统一**：使用单个 `…`；范围、数量和单位格式后续随文案替换一并检查。
10. **代码标识不随界面术语强制重命名**：本轮统一用户语言，不要求把 `Card`、`Identity` 等工程符号批量改名。
11. **身份称谓先全称、后简写**：正式定义、功能介绍或首次出现用“扩列卡片”；上下文明确后用“卡片”，避免同句反复出现全称。
