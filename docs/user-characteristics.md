# 用户特征与交互约束

## 文档目的

碰碰娃主要服务于展会、聚会和外拍等线下场景中的 kigurumi 玩家。部分用户会佩戴头壳、手套，并穿着肉色打底衣等完整装扮；这些装扮可能同时限制视野、触控精度和动作灵活度。

核心目标：**用户保持完整装扮时，也能快速看清状态，并用少量、宽松的操作完成名片交换。**

本文是基于典型装扮特征整理的设计约束，不是用户访谈或统计结论。不同用户的装扮和辅助方式差异很大，不应假设所有 kigurumi 玩家都有相同能力或需求。

## 典型特征与设计影响

| 用户特征或现场条件 | 可能的操作困难 | 设计要求 |
| --- | --- | --- |
| 佩戴头壳，观察范围和角度受限 | 难以扫视整页、看清边缘信息或发现页面变化 | 当前状态和主操作集中呈现；关键信息不依赖余光、长页面滚动或短暂提示 |
| 手套、肉色打底衣等装扮降低手指灵活性 | 小按钮容易点错，精细滑动、双击和多指手势难以完成 | 使用大触控区域和明确按钮；核心功能不依赖精细手势、长按或悬停 |
| 需要同时持手机、道具或与对方配合 | 难以双手操作或连续完成多个步骤 | 支持单手完成主流程；减少页面跳转、重复确认和手动输入 |
| 展会人流密集、环境嘈杂 | 容易错过声音提示，操作容易被打断 | 状态以常驻文字和图形为主，触感反馈为辅；中断返回后仍能看懂当前进度 |
| 光线复杂，手机屏幕可能倾斜或离面部较远 | 小字、低对比度和仅靠颜色表达的状态难以识别 | 使用清晰字号、足够对比度和简短文案；成功、等待、失败必须有文字区别 |
| 装扮穿脱不便，现场时间有限 | 为纠错反复进入系统设置或重新操作的成本较高 | 异常提示直接说明原因和恢复动作；保留扫码等可替代入口 |

## 核心交互原则

### 1. 先完成交换，再提供扩展能力

NFC 碰一碰、二维码和附近娃娃是现场核心功能。默认首屏应直接呈现可用的交换入口，不让用户先经过装饰性内容、复杂设置或多层页面。

- 优先保留自动识别和自动推进的步骤，避免要求双方反复选择模式。
- 同一时刻只突出一个主操作，例如「出示我的二维码」「扫一扫」或「申请交换」。
- 非现场必需的编辑、排序、记录管理等功能不得挤占核心状态和主操作。
- 交换过程中避免强制输入文字；必须确认时，使用含义明确的按钮，而非只显示图标。

### 2. 操作目标要大、少、容易碰触

- 所有可点击元素至少满足 Android **48×48dp** 触控区域；核心按钮建议使用不小于 **56dp** 的有效高度，并与相邻操作保留足够间距。
- 核心操作优先使用整行或通栏按钮，不使用角落小图标、紧密排列的文字链接或精确点按码区。
- 不用双击、多指、精细拖拽或长按作为唯一入口；若提供快捷手势，必须同时保留可见按钮。
- 高风险操作与主操作分开，避免等待交换时误触取消、返回或删除。
- 主操作尽量位于单手容易触及的区域，但当前状态必须与它在同一视野内可辨认，不能为了贴底而把状态推到远处。

### 3. 一眼看懂当前状态和下一步

每个交换页面只回答三个问题：**现在正在做什么、是否成功、接下来要做什么。**

- 使用「等待对方同意」「已加入集邮册」「请开启蓝牙」等直接文案，避免只显示技术术语或动画。
- 当前状态、主要异常和主操作应在首屏形成连续的信息组，不要求上下滚动后才能拼出完整含义。
- 状态变化不能只靠颜色、toast、声音或短暂动画表达；关键结果应持续显示，直到用户离开或开始下一次操作。
- 图标必须配合文字或无障碍名称；二维码、NFC 和蓝牙图形只辅助理解，不替代操作说明。
- 遵循系统字体缩放和深浅色设置；放大字体后优先保住状态与主按钮，次要信息可以换行或下移。

### 4. 允许打断、恢复和替代

现场操作可能随时被他人、合影或设备状态打断。返回页面后，应保留真实进度并给出明确下一步，不让用户猜测是否需要重新开始。

NFC、扫码和附近娃娃互为补充。设备不支持、权限被拒或识别失败时，提供可行的替代入口；不得把尚未恢复的失败状态显示为等待中。

## 核心流程要求

| 流程 | 装扮状态下的目标体验 |
| --- | --- |
| NFC 碰一碰 | 打开主页即可理解如何靠近手机；无需精准点击开始；设备未就绪时有明显恢复入口 |
| 出示或扫描二维码 | 二维码足够大且对比清楚；扫码入口容易点按；取景页只保留必要提示和退出操作 |
| 附近娃娃交换 | 名字、状态和「申请交换」按钮清楚分离；等待期间防止重复提交；对方同意或拒绝后结果持续可见 |
| 权限或设备异常 | 一句话说明缺少什么，并提供「去授权」「开启蓝牙」等实际可执行的恢复动作 |
| 交换完成 | 不依赖听觉或精细视觉即可确认成功；无需额外操作即可开始下一次相遇 |

## 设计与验收清单

涉及核心交换流程的设计或变更，至少检查：

- [ ] 单手、戴手套或触控精度降低时，能否完成主流程并避免误触？
- [ ] 不扫视整页、不滚动页面时，能否看清当前状态、结果和下一步？
- [ ] 核心按钮是否足够大，相邻按钮是否有间隔，是否存在只能精细手势完成的操作？
- [ ] 关闭声音、不看短暂提示、无法分辨颜色时，是否仍能理解等待、成功和失败？
- [ ] 系统字体放大后，主状态和主操作是否仍完整可见，按钮文案是否被截断？
- [ ] 操作被打断后返回，是否显示真实进度和可执行的恢复路径？
- [ ] 是否保留至少一种不依赖精细触控的替代交换方式？

以上清单用于设计评审和真机验证，不代表仅凭静态截图即可完成验收。条件允许时，应邀请实际佩戴头壳和手套的用户参与测试，并记录装扮类型、设备、完成步骤和误触情况；测试记录不得包含可识别个人身份的信息。
